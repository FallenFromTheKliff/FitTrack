# Aesthetic Source Ladder

Use this rubric to stop premium UI runs from treating polished-but-safe product UIs as the full visual answer.

## Ceiling classes

- `high_ceiling`
  - produces visible first-glance identity
  - has strong material language, typography posture, or component atmosphere
  - can push a concept away from generic premium SaaS
- `mid_ceiling`
  - polished and useful, but still likely to resolve into safe product UI without stronger art direction
  - often best for workflow truth, density, or domain fit
- `low_ceiling`
  - generic templates, roundup blogs, vague gallery shots, or weak screenshots
  - should not guide premium art direction

## Preferred aesthetic leads

- Awwwards captures in `UI Design`, `Interaction`, or `Animation`
- Cult UI
- Hover.dev
- Aceternity UI
- Magic UI direct MCP when the page family and structure are already stable

## Support-only references

These can help with domain realism, operator truth, or product plausibility, but they should not be the sole aesthetic lead:

- Garmin Connect or similar performance products
- Cal.com
- Attio
- Linear
- BellaBooking
- Gymdesk
- Gymflow
- other polished utility SaaS products

## Approval rules

- The aesthetic lane must include at least two screenshot-backed `high_ceiling` references.
- Each approved aesthetic source must declare:
  - `source_ceiling`
  - `aesthetic_role`
  - exact visual traits being borrowed
  - exact traits being rejected
- If the lane relies only on support-only references, it is `weak`.
- If the captures show only full-page screenshots with no cropped anatomy or trait notes, the lane is `weak`.
- If the sources could plausibly produce a tasteful generic dashboard with no first-glance identity, the lane is `weak`.
